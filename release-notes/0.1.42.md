- **NuGet sources per solution:** Settings › Languages › .NET has a new **Environment variables** table, saved with the project. Every restore, build, test and run gets these variables, and so does the C# language server. MSBuild reads each one as a property, so `RestoreSources=/path/to/packages;https://api.nuget.org/v3/index.json` restores from a local folder and nuget.org when the solution's `nuget.config` names a feed you can't reach. Changing them restores the solution again.
- **Automatic NuGet restore:** packages are restored in the background when a solution opens, when a project file, `Directory.*.props` or `nuget.config` changes, and when the C# language server finds unresolved packages. Errors show in Problems on the project they belong to. Turn it off in Settings › Languages › .NET.
- **Dependencies in the Solution view:** each project lists its frameworks, packages (with the packages they bring in) and project references, per target framework.
- **Build button for .NET:** the title bar's Build Project button now shows for .NET solutions and dotnet run configurations. Project files no longer show under their project node; open one from the project's Edit menu.

macOS builds are not notarised yet: the first time, right-click Bayonet in Applications and choose **Open**.
